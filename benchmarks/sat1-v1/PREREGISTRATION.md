# SAT-1 v1: staged operation-count saturation

SAT-1 asks how many distinct quantity operations the fixed 4,852,992-parameter
student can route and execute before the frozen quantity gates fail. The
design holds total records, update opportunities, initialization, replay
authority, and parameter count fixed. Only the number of operation types
changes.

The six declared counts remain 5, 10, 20, 40, 80, and 160, with one nested
operation inventory and three declared seeds. Running all 18 training arms at
once is rejected as the opening move. The study is staged so each AWS spend is
budgeted from measured timing and each expansion has a frozen reason.

## Current readiness: blocked at the anchor

The frozen Q2.6 seed-2 model is already the declared five-operation anchor; it
must not be retrained as a new SAT-1 arm. It passes the three-seed quantity
family rule, but the completed external screen fails the prospective language
gate: BLiMP passes, while TinyStories is 1.681% worse than ZERO.3 against a 1%
allowance. The conjunctive gate therefore fails.

SAT-1 scientific compute is blocked until a separately preregistered
five-operation repair candidate preserves the existing quantity/replay result
and passes the language gate. Deterministic inventory and validator mechanics
may still be built, but no timing or training arm is authorized.

## Stage 0 — mechanics and timing

Build and freeze the 160-operation inventory, deterministic nested datasets,
split-isolation checks, and result validator. Then, under a separate hard
budget and only after the anchor is unblocked, measure one score-sealed AWS
timing unit. Stage 0 makes no scientific claim and authorizes no later stage.

## Stage A — three-point seed-2 screen

Reuse the frozen count-5 Q2.6 seed-2 anchor without retraining, then run counts
40 and 160 on diagnostic seed 2 only after the anchor is unblocked. Each
prospectively selected arm checkpoint must clear the inherited quantity/replay
gates and the candidate-only language gate.

- If count 5 fails quantity or language, stop: the study has no valid anchor.
- If count 40 or 160 fails language, stop and report a language-preservation
  boundary rather than calling it routing saturation.
- If count 160 passes both, skip interpolation: the screen found no transition
  through 160.
- If a larger count fails quantity while language is preserved, Stage B may
  localize the transition.

## Stage B — localization, only if needed

Run counts 10, 20, and 80 on seed 2. Sort all valid diagnostic arms and select
the adjacent highest passing and lowest failing quantity counts. The selection
function is fixed here; replication outcomes cannot change the bracket.

## Stage C — replication

If Stage A passes through 160, replicate counts 5 and 160 on seeds 1 and 3.
If Stage B finds a bracket, replicate those two adjacent counts on seeds 1 and
3. All four replication arms run even if an earlier arm fails. A count is
confirmed only when seeds 1, 2, and 3 all clear the public, promotion, replay,
and language gates.

Every stage needs a separate immutable AWS budget and explicit authorization.
No training, timing run, workflow dispatch, or collector is authorized by
this preregistration.
