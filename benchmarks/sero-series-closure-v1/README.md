# Sero series closure

Sero is frozen as a completed conventional CUDA scaling demonstration. Its
code, contracts, failed latent-tokenizer designs, results, and hashes remain
available. No larger main-line Sero run is authorized.

The terminal 20M result passed every frozen quality gate and cut matched-token
test bits per raw byte by 9.56% versus the 6M model. It still produced repeated
phrase loops and locally false arithmetic. The supported conclusion is “scale
improved compression,” not “scale produced intelligence.”

The active model line returns to dependency-free C11 ZERO. Solomon remains the
separate integer-only Rust line. ilXyr remains the evidence and control plane.

## Dense scale price tags

These are compute planning ranges, not fixed quotes. The low end assumes an
optimized H100 cluster at 250 effective TFLOP/s, current AWS Capacity Block
pricing, and 30% normal run overhead. The high end scales the measured Sero
20M A10G pipeline at constant tokens per parameter and adds the same overhead.
Until a paid distributed benchmark exists, use the high end.

| 1B | 20B | $750 | **$8.9K** |

The 1P row is arithmetic, not a credible dense training proposal. It would
require about 133 trillion H100-hours under these assumptions.

The range excludes data, rights, synthetic generation, engineering,
distributed-system work, failed runs, storage, evaluation, and serving. See
[SCALE-COSTS.json](SCALE-COSTS.json) for the exact formula and machine-readable
values.

## Policy

A larger Sero run is a separate paid project. It must fund, before launch:

1. corpus and rights work;
2. a small distributed throughput benchmark;
3. a frozen training and evaluation contract;
4. the quoted compute budget and failure reserve; and
5. artifact storage and delivery.

This closure does not prevent a future customer-funded run. It prevents that
run from silently consuming the ZERO research budget.
